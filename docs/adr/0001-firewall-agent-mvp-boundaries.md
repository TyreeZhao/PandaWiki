# ADR-0001: 防火墙 Agent MVP 的跨仓边界与执行安全模型

Status: accepted
Date: 2026-08-12

## 背景 / 问题

客户希望基于 PandaWiki 中的防火墙 GB 标准进行知识问答，并让 Agent 辅助执行防火墙操作。知识检索是低权限读路径，设备变更是高风险写路径。若把知识、模型编排、审批和设备权限放入同一组件，会扩大攻击面，也难以证明 Prompt Injection 或模型误判无法绕过安全规则。

MVP 还受到以下约束：

- 复用现有单机 PandaWiki 和 Agent Compose。
- 不连接生产防火墙，只使用有状态模拟器。
- 只允许临时封禁一个文档测试网段中的单个 IP。
- 后续需要把模拟器替换为真实厂商设备适配器。
- Firewall MCP 是我方正式交付组件，部署在客户私有环境。

## 决策

采用三个职责分离的组件：

1. PandaWiki 仅提供知识管理、检索和条款级证据。
2. Agent Compose 提供独立 UI、模型调用和工具编排，但不作为授权或安全事实源。
3. 独立 Firewall MCP Server 负责所有设备状态、规则校验、审批、执行、验证、回滚、自动解除和审计。

Firewall MCP 使用独立仓库、Go、`mcp-go`、SQLite 和独立容器镜像交付。其公开契约仅包含六个只读工具以及 `prepare_change`、`apply_approved_change` 两个写流程工具。

写操作使用两阶段审批。审批页面独立于 Agent，对批准接口进行认证和 CSRF 防护。审批凭证绑定变更 ID 和冻结参数摘要，15 分钟失效且只能原子消费一次。Agent 无批准权限、Shell、Docker Socket、数据库文件或设备底层权限。

## 备选与否决理由

### 在 PandaWiki 内实现 Agent 和防火墙执行

否决。会把知识系统与高风险执行路径耦合，扩大 PandaWiki 修改面，也不利于独立交付和真实设备适配。

### Agent 直接使用 Shell、CLI 或 Docker Socket

否决。权限范围远超临时封禁所需能力，难以做参数级审批、幂等、精确回滚和稳定审计。

### 仅用 Prompt 限制 Agent

否决。Prompt 不是安全边界，无法可靠抵御 Prompt Injection、模型错误和工具参数篡改。

### 采用多 Agent 分离权限

否决用于 MVP。多 Agent 会增加编排复杂度，但仍不能替代 Firewall MCP 的确定性授权和状态机。

### 直接连接生产设备

否决用于 MVP。在知识证据质量、授权、审批、幂等、恢复和 Eval 未通过前，不应承担真实设备风险。

## 退化 / 保留

### 退化

- MVP 只支持单设备模拟器、单测试网段和一种临时写操作。
- SQLite 和单机任务恢复存在单点风险。
- 同一自然人可作为发起人和审批人，不满足严格职责分离。
- 一次性审批码会短暂进入 Agent 对话上下文。

### 保留

- 保留知识系统、模型编排和执行安全边界的清晰职责。
- 保留未来替换真实设备适配器的稳定 MCP 契约。
- 保留参数冻结、独立审批、幂等、验证、回滚和审计闭环。
- 保留从单机 MVP 向企业 IAM、服务端审批回调、多机和高可用演进的路径。

## 架构影响 / 后果

正面后果：

- Prompt Injection 或 Agent 错误不能直接形成设备授权。
- Firewall MCP 可以独立测试、版本化、部署和交付。
- 模拟器和真实设备适配器可共享上层工具契约和状态机。
- PandaWiki 原则上无需修改业务代码。

负面后果：

- 增加一个独立服务、仓库、镜像、数据库和审批页面。
- 跨组件认证、网络和错误恢复需要额外集成测试。
- 单机 SQLite 和任务调度只适用于 MVP，不是最终生产架构。

可逆性：

- Agent Compose 可替换为其他支持 MCP 的编排底座。
- SQLite 可在生产阶段迁移为支持高可用的数据库。
- 模拟器可通过适配器替换为真实设备，而不改变 Agent 的核心交互。
- 审批码可替换为企业审批系统的服务端回调。
